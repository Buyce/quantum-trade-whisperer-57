## 2. What A2A delivered

**R1 — identity compatibility.** `structureKeyOf` retains versioned 5-decimal
rendering; 117/117 live Wave 0 signals reconcile. Pinned by
`structure-key-parity.test.ts`. The earlier "122" figure was a query over a
wider window, not a mismatch.

**R2 — tick/role-aware geometry.** `normalizeOrderGeometry` snaps by role (a stop
never moves toward entry, a target never moves nearer), reports
`source: "unnormalized"` and `tick: null` rather than inventing a grid. Spread,
stops-level, risk and sizing checks in `revalidate.server.ts` now run against
post-normalization geometry, and `execution_deliveries` stores
`published_entry/stop/target` plus `price_grid_*` so published vs submitted
geometry is durably reconstructable.

**R3 — last-moment execution gate.** `assertCapability` re-reads the stage
immediately before every irreversible act: MetaApi submission
(`direct.server.ts`), bridge POST (`dispatch.server.ts`), alert fan-out
(`alerts.server.ts`). A refusal settles the delivery with `lifecycle_refused`.

**R6 — research write gate.** `observations.server.ts` filters per instrument,
`candidates.server.ts` re-reads before insert, and enrolment moved to the atomic
RPCs `claim_and_enrol_model_shadow` / `enrol_research_candidate_shadow`, so
claim + insert + bookkeeping commit together or not at all.

**Fail-closed semantics.** A degraded lifecycle read refuses every capability
outside the frozen Wave 0 set and allows Wave 0 only — pinned by
`phase-a2a-gates.test.ts` and `final-boundary-gate.test.ts`.

**R4 — suspension recovery.** `pre_suspension_stage` recorded; restoration runs
through `transition_instrument_stage` (audited), never a direct update.

**Dark schema.** `instrument_spread_samples`, `instrument_atr_snapshots`,
`instrument_capability_allowed` RPC, delivery provenance columns.

## 5. Operational checklist — A2B lifecycle-enforcement checkpoint

Entry requires ALL of the following; each is a separately authorised step.

1. **Sampler runtime authorised and deployed** (A2B scope): a bounded endpoint
   writing `instrument_spread_samples` and `instrument_atr_snapshots` under a
   provider budget, plus its schedule.
2. **Evidence accumulated** per Wave 1 symbol before any stage change:
   - spread samples spanning all trading sessions over a stated window;
   - broker spec row present with `digits`, `point`, `stops_level`,
     `volume_min/step`, `trade_mode`;
   - a derived (never guessed) `spreadFloor` recorded with its derivation.
3. **Per-account symbol mapping resolved** for every Wave 1 symbol on every
   connected account (R8), with unmapped symbols refused, not defaulted.
4. **Conversion readiness proven** (R5): quote-currency conversion available for
   USDJPY/USDCHF/USDCAD sizing, else sizing must refuse.
5. **Current-candle policy pinned** (R7) by test: which bar the scanner may read.
6. **Enforcement dry-run.** Flip `lifecycle_enforced = true` while all Wave 1
   symbols remain `disabled`. Expected: zero behaviour change for Wave 0, and
   logs show gate decisions rather than degraded reads. This is the checkpoint.
7. **Rollback path rehearsed.** Set `lifecycle_enforced = false`; confirm Wave 0
   unaffected. Stage rollbacks use `transition_instrument_stage` only.
8. **Then, and only with explicit approval, first Wave 1 transition:**
   `disabled -> data_validation` for one symbol, via
   `transition_instrument_stage` with reason, approver and evidence — data
   collection only, no research, no publication, no execution.

No step here authorises `shadow`, `signals_only` or `execution_approved` for any
Wave 1 symbol; those are A2C decisions gated on accumulated evidence.
